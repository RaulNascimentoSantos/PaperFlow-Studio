1. VISÃO GERAL DO PROJETO
================================================================================

O PaperFlow API é uma solução completa para transformar documentos em inteligência
de dados através de processamento avançado com IA. O sistema oferece:

• Processamento inteligente de PDFs
• Extração de texto, tabelas e dados estruturados  
• Análise e classificação de documentos
• Sistema de perguntas e respostas (RAG)
• OCR para documentos escaneados
• API REST completa com autenticação
• Sistema de usage analytics
• Documentação Swagger/OpenAPI

CARACTERÍSTICAS PRINCIPAIS:
- Arquitetura escalável e modular
- Integração com OpenAI GPT-4 e embeddings
- Sistema RAG (Retrieval-Augmented Generation)
- Processamento assíncrono com filas
- Cache distribuído com Redis
- Storage compatível com S3
- Monitoramento e observabilidade

================================================================================
2. ARQUITETURA E TECNOLOGIAS
================================================================================

STACK TECNOLÓGICO:
• Node.js 20 LTS + TypeScript 5.3
• Fastify 4.x (Framework web)
• PostgreSQL 16 + pgvector (Banco principal)
• Redis 7 (Cache e filas)
• OpenAI API (IA e embeddings)
• BullMQ (Processamento de filas)
• Tesseract.js (OCR)
• PDF-Parse + PDF2pic (Processamento PDF)
• S3 Compatible Storage
• Docker + Docker Compose
• Swagger/OpenAPI 3.0

PADRÕES ARQUITETURAIS:
• Clean Architecture
• Dependency Injection
• Adapter Pattern (para provedores IA)
• Repository Pattern
• Factory Pattern
• Observer Pattern (eventos)

PRINCÍPIOS DE DESIGN:
• SOLID principles
• Separation of Concerns
• Single Responsibility
• Open/Closed Principle
• Interface Segregation

7. SISTEMA DE AUTENTICAÇÃO
================================================================================

🔐 ESTRATÉGIA DE AUTENTICAÇÃO:
• API Keys no formato: pf_live_xxxxxxxxxxxxxxxx (produção)
• API Keys no formato: pf_test_xxxxxxxxxxxxxxxx (teste)
• Validação via header: x-api-key
• Hash seguro com bcrypt (10 rounds)
• Cache distribuído para performance

🔐 PROCESSO DE REGISTRO:
1. POST /v1/auth/register com email, company, plan
2. Geração automática de API key + secret
3. Hash seguro e armazenamento no banco
4. Retorno das credenciais para o usuário
5. Associação automática de créditos por plano

🔐 FLUXO DE VALIDAÇÃO:
1. Extração do header x-api-key
2. Validação do formato (pf_live_* ou pf_test_*)
3. Busca em cache Redis (performance)
4. Se não encontrado, consulta ao banco
5. Comparação segura com bcrypt.compare()
6. Cache do resultado (TTL: 5 minutos)
7. Atualização do last_active

🔐 SEGURANÇA IMPLEMENTADA:
• Rate limiting: 100 req/min por IP
• Hash seguro das API keys (bcrypt)
• Validação de formato rigorosa
• Cache com TTL para evitar ataques
• Logs de tentativas de autenticação
• Headers de segurança (helmet)
• CORS configurável por ambiente

🔐 GESTÃO DE CHAVES:
• Rotação automática disponível
• Múltiplas chaves por usuário (futuro)
• Revogação instantânea
• Auditoria completa de uso

COMPONENTES:
1. Document Chunking:
   • Divisão inteligente em chunks de 1000 tokens
   • Preservação de contexto semântico
   • Overlapping de 200 tokens
   • Metadata associada (página, posição)

2. Embedding Generation:
   • Geração via OpenAI ada-002
   • Armazenamento em PostgreSQL (pgvector)
   • Batch processing otimizado
   • Cache para evitar recálculos

3. Vector Search:
   • Busca por similaridade coseno
   • Filtros por documento
   • Ranking por relevância
   • Threshold configurável (0.7)

4. Context Construction:
   • Seleção dos top-5 chunks relevantes
   • Construção de contexto estruturado
   • Preservação de fonte e página
   • Otimização para prompt engineering
